# Beekeeper — Build Log

Running log of what was built, problems hit and how they were fixed. Newest milestone last.

## Environment (build machine)

- Windows 11 (NT 10.0.26300), PowerShell 5.1, Node v26.13.0, npm 12.2.0, git 2.56, gh 2.103
- Electron 45.2.1 (latest stable at build time; Chromium 156, Node 24), Vite 8, electron-vite 6, React 18.3, TypeScript 5.9 (strict + `noUncheckedIndexedAccess`), Tailwind CSS 4
- Project lives inside OneDrive (`...\OneDrive - Microsoft\Desktop\Beekeeper`); every path is quoted in all commands.
- The build ran fully autonomously: the work was split into foundations written directly and leaf modules (icons, models, OCR, commands, system layer, settings UI, onboarding UI) written by parallel sub-agents against the shared contracts in `src/shared`, then integrated, reviewed and verified end to end.

## Milestones

### M1 — Scaffold (done)

- electron-vite 6 + Vite 8 + React 18 + TypeScript strict (`noUncheckedIndexedAccess`) + Tailwind 4; multi-window ready: renderer pages and preload bridges are auto-discovered from `src/renderer/<name>/index.html` and `src/preload/<name>.ts`.
- Tooling: ESLint 9 flat config (typescript-eslint type-checked, react, react-hooks, jsx-a11y, bans `eval`/`new Function`/`exec`), Prettier, Vitest 5 (+v8 coverage thresholds 80 % for `src/main/commands` and `src/shared`), Playwright config.
- CI workflow (`.github/workflows/ci.yml`), issue/PR templates, MIT license, `.gitignore` (models, traineddata, binaries, env never committed).
- Evidence: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` all exit 0; built Electron app launched, window title "Beekeeper", responsive, all child processes exited cleanly.

### Contracts (between M1 and M2)

- Shared card model, command/system contracts, text helpers and a `JsonStore` (`f2a200e`) so that parallel work could not drift apart.

### M2 — Design system, motion, icons, orb (done)

- Tailwind design tokens (honey / coral / violet / cyan palette), glass surfaces, spring and ease tokens that collapse under reduced motion, a component gallery page for visual QA.
- Canvas orb with idle, listening, thinking, speaking and error states; cards, chips, buttons.
- Icons generated from code (`scripts/gen-icons.mjs`): app icon in 16-256 px `.ico` and `.png` set, tray frames per theme and state, NSIS sidebar/header art.
- Evidence: unit tests for the pure motion/orb maths; gallery reviewed visually.

### M3 — Shell (done)

- Window manager with pre-created hidden windows per role (sandboxed preloads, per-window CSP, navigation and `window.open` blocked), tray, single instance, global hotkeys with conflict detection and suggestions, settings store with per-section validation, `safeStorage` secrets, log rotation (5 × 5 MB), updater controller.
- IPC: every channel declared once in `src/shared/ipc/{channels,schemas}.ts`, role allow-lists, zod validation in main, trusted-sender check.
- Evidence: unit tests for CSP, routes (path traversal), placement, settings, IPC contract consistency; E2E "tray exists, tooltip, single instance".

### M4 — Assistant bar and commands 1-17 (done)

- Command engine (scored matchers, synonyms, fuzzy typo repair, slot extraction, last-5-turn follow-ups), registry with duplicate checks, web-search fallback.
- Commands 1-5 apps & web, 6-12 info (safe maths parser without `eval`, unit converter, weather via Open-Meteo, dictionary), 13-17 productivity (timers, persisted reminders, alarms, notes, copy-that), each with its own tests.
- Assistant UI: glass bar, streaming answer cards, weather/timer/calc/confirm/gallery cards, history recall.
- Evidence: 41 command test files; a cross-command routing test sends 230 phrases (synonyms, typos, shouted/padded variants) through the real registry.

### M5 — System commands 18-25 (done)

- Volume, brightness, battery, system info, apps index (Start menu `.lnk` + packaged apps, aliases, fuzzy ranking), screenshot, lock, recycle bin, power, dark mode, `ms-settings:` pages. All OS access through `execFile` with argument arrays and ASCII-only bundled PowerShell scripts; shutdown/restart/sleep/recycle bin need a confirmation with a 10 s cancel countdown.
- Evidence: unit tests with fake system APIs (99.9 % statement coverage of `src/main/system`), opt-in live tests (`BEEKEEPER_LIVE=1`) for the read-only parts. See incident #23.

### M6 — Voice (done)

- Vosk model manager (pinned manifest, mirrors, resume, SHA-256), AudioWorklet capture, VAD / endpointing, live transcript, push-to-talk, system TTS, earcons, click-through edge glow window.
- Evidence: E2E with a fake microphone playing a WAV that Windows' own voice synthesised from "what time is it": the offline model transcribes it and the answer card appears (no keys involved). Problems #10 and #11 were found by this test.

### M7 — Wake word (done)

- "Hey Beekeeper" in a hidden worker: an energy gate in front of a Vosk keyword grammar, pause while the bar is open and on Battery Saver, tray "armed" state; off by default.
- Evidence: E2E with a fake microphone saying "hey beekeeper" opens the bar; unit tests for the gate and the controller.

### M8 — Circle to Search (done)

- Capture (DPI and multi-monitor aware), pre-created transparent overlay with a ready handshake, glowing lasso with smoothing and bounding box, morph to a selection box, tap word / double-tap line / Shift-drag rectangle / keyboard selection, offline Tesseract OCR on the crop (2× upscale for small text), smart actions (links, e-mail, phone, dates, maths), results sheet, copy/save image, search and translate in the browser.
- Evidence: E2E draws a lasso on a rendered "screen" and reads `Beekeeper circles words`; tap selects a word; `Esc` leaves no overlay or session behind. Problem #14 (capture speed) fixed here.

### M9 — Azure (done, not testable with real keys)

- Azure OpenAI client (plain `fetch` + SSE; streaming chat and vision) behind an `AnswerStreamer`, speech-token broker, lazy Azure Speech SDK in the assistant window (push-stream recognition, SSML TTS), engine selection with automatic fallback to the offline engines, connection tests in Settings > AI.
- Evidence: unit tests with fakes for the HTTP client, SSE parsing, error mapping and the SDK. **Limitation:** no Azure subscription was available, so the cloud paths were never run against the real services.

### M10 — Settings and onboarding (done)

- Settings: General, Voice, Hotkeys (recorder, conflict help), Circle to Search, AI, Privacy, Updates, About — instant, validated persistence; five-step onboarding (welcome, microphone test, voice model, hotkeys & wake word, recap with confetti); keyboard navigation, live regions, reduced-motion variants.
- Evidence: ~450 renderer tests for the two windows; E2E "settings change persists across restart" and "onboarding appears on the first launch only".

### M11 — Performance, security, E2E, screenshots (done)

- Perf spec asserts the budgets on the real app; measurements below. Security pass: CSP unit tests, IPC role checks, path guard, `npm audit` (no high/critical), secret scan of the whole history.
- README screenshots are generated by `tests/e2e/docs-screenshots.spec.ts` from the running app on a neutral wallpaper (no personal desktop content).

### M12 — Packaging, update, CI/release, docs (done)

- electron-builder NSIS (per-user, choose directory, desktop and Start menu shortcuts, run after finish) and portable; `electron-updater` against GitHub Releases (disabled for portable); release workflow on `v*` tags; README, CHANGELOG, SECURITY, PRIVACY, CONTRIBUTING.
- Output is built outside OneDrive (`BEEKEEPER_BUILD_OUT=%LOCALAPPDATA%\beekeeper-build`) and the two executables, the blockmap and `latest.yml` are copied to `/release`. Installer 117.1 MB (122,774,752 bytes), portable 105.1 MB; `latest.yml` carries the SHA-512 of the installer, checked against a freshly computed hash.
- Packaged-build verification (see acceptance list): full E2E suite run **against `win-unpacked\Beekeeper.exe`** (`BEEKEEPER_EXE`), portable exe launched (log `packaged, portable`, `Tray ready 172 ms after launch`), NSIS installer installed silently into a temp folder (exit 0, shortcuts created), the installed app launched (`Tray ready 170 ms after launch`) and uninstalled again (folder, shortcuts and registry entry gone).

## Security and dependency audit

- `npm audit` (full tree): 14 moderate, **0 high, 0 critical**. They come from `minimatch` through the ESLint toolchain (dev only) and `uuid` inside `vosk-browser` (the advisory is about `v3/v5/v6` with a caller-supplied buffer; the recogniser only creates random `v4` ids). The production-only audit was rate limited by the corporate registry proxy (HTTP 429), so the full-tree result is the one recorded.
- CSP, IPC role checks, path guard and navigation blocking have unit tests; `unsafe-eval` exists only for the Vosk worker script (SECURITY.md).
- The only native module is `koffi` (MIT, prebuilt N-API binary) for the GDI screenshot.

## Known limitations (honest)

- **Azure Speech and Azure OpenAI were never run against real services** (no subscription on the build machine). The clients, the SSE parser, error mapping, token broker, engine fallback and the Settings UI are unit-tested with fakes only.
- **Builds are unsigned**, so SmartScreen warns on first run. `electron-updater` is wired and `latest.yml` is published, but the update flow itself could not be exercised end to end with only one release in existence.
- **English only** (Vosk small English model, English OCR data, English UI strings).
- The wake word was tested with synthesised speech and a fake microphone; real-world false accepts/rejects were not measured. Wake word on costs about 380 MB and 2-3 % CPU.
- Multi-monitor and mixed-DPI behaviour is covered by unit tests of the coordinate mapping and was verified live on one 1920×1080 display at 150 % scaling.
- Not run live on the build machine: mute, dark-mode and sleep writes, launching and closing real apps (UWP closing included), shutdown and restart (never run automatically), and the opt-in `BEEKEEPER_LIVE` tests beyond their read-only parts. Constrained Language Mode machines cannot compile the PowerShell helpers.
- DRM-protected video is black in any screenshot, including Circle to Search.
- The tray's "microphone active" indicator is not driven by the Settings / onboarding microphone tests (they show an in-window indicator instead).
- The local test session was locked during the final verification, so the two real key-press tests report as skipped there; they passed on GitHub's hosted Windows desktop.
- An earlier incident of this build (a `-WhatIf` dry run that really emptied the Recycle Bin, problem #23) is documented above.
